# axon

Native terminal emulator: minimalist, Wayland/X11 and Windows, Rust. On Wayland it runs on an own client and a CPU renderer into `wl_shm`
(`knowledge/decisions/core/0011`, `0013`; idle RSS 19 MB); the `winit` + `wgpu` path remains only for X11 and as fallback until stage E. On Windows the same app runs over an own Win32 layered window (`win.rs`, behind the `plat.rs` seam, ADR 0039; ConPTY shell, PowerShell by default). Do not confuse "Windows" the OS with the app's windows (panes, groups) below.
VT emulation: `alacritty_terminal`. Window: own `wl.rs` on Linux, own `win.rs` on Windows (`winit` fallback on X11). Keyboard layouts: `libxkbcommon` via `dlopen` (`xkb.rs`). Glyphs: `fontdue` + tiles.
Direction: data-oriented, no caches, own implementations instead of dependencies (`knowledge/decisions/core/0009`, `0010`, `0011`);
`alacritty_terminal`, `fontdue`, `winit` and `wgpu` are scaffolding.

## Commands
- `cargo run --release` — run (debug is too slow for rendering).
- `cargo build --release` — fat LTO, `panic=abort`, strip.
- `scripts/design.sh [--baseline]` — renders the design board frames from the real renderer (`src/design.rs`) into
  `design/frames/`; open `design/board.html`. `--baseline` keeps the previous frames to compare. Use it for every visual change.
- `scripts/install.sh [--prefix DIR] [--no-build] [--uninstall]` — installs the binary, desktop entry and icon (`assets/`); `DESTDIR` is honoured. Test it with a throwaway `DESTDIR` or `HOME`, never the real one. Copied into release bundles, where it installs the files beside it.
- Windows (ADR 0039, 0040): cannot be run here; `cargo check --release --target x86_64-pc-windows-msvc --tests` proves it builds, and `.github/workflows/windows.yml` (on `windows-latest`) builds, runs the app's own self-test (`AXON_SELFTEST=<dir>`, `scripts/selftest.ps1`: a real window and PowerShell; the artifact has `selftest.txt` and `frame.png`, convert a frame with `scripts/argb2png.py`), the tests, and the package + `install.ps1`/`get.ps1` round trip. Look at the artifact for a visual change on Windows. `scripts/package.ps1` packs `axon-x86_64-windows.zip`; `scripts/get.ps1` is the `irm | iex` installer (served as `install.ps1`); `scripts/install.ps1` installs from the zip or a checkout. A change to `win.rs` or anything `cfg(windows)` needs the CI green before it is done.
- Distribution (ADR 0035): `scripts/package.sh [--no-build]` packs `target/dist/axon-<arch>-linux.tar.gz` + `.sha256`; a tag `vX.Y.Z` (= `Cargo.toml` version) runs `.github/workflows/release.yml` (Ubuntu 22.04, x86_64 and aarch64, glibc 2.35). `scripts/get.sh` is the `curl | sh` installer of a release (POSIX sh; `AXON_RELEASES=file://...` points it at local bundles for tests). The website is `site/` (one static page in English and Spanish: English is the markup, Spanish the dictionary at the end of `index.html`, keyed by `data-i18n*`; a new string needs both; frames in `site/shots/`); `scripts/site.sh [--serve] [--shots]` builds it into `target/site/` with `get.sh` as `install.sh` and `get.ps1` as `install.ps1` (a Linux/Windows picker shows each system's commands); `.github/workflows/pages.yml` publishes it.
- Settings: `axon config` creates `~/.config/axon/config.toml` (`config edit`, `config show`, `config path`; own parser in `config.rs`; `assets/config.example` lists every key; `Ctrl+Shift+R` reloads in `wl`; the settings panel (docked beside the grid, non-modal; gear in the title bar or `Ctrl+,`, `settings.rs`, ADR 0026) edits and saves it as you change things; `AXON_SETTINGS=1` starts with it open, for screenshots and measurements). The window's text is in English or Spanish (`i18n.rs`, `[ui] language`, ADR 0022: a new string goes in `strings!` for both languages). The look follows the `terminal.html` reference (ADR 0021, 0036, 0037: amber accent, hairlines, a proportional UI font around the monospaced grid (`UiFont`, held by `Soft`, its character map narrowed by `cmap.rs`), quiet chips, 22 px margins, the shell's prompt docked at the bottom below a hairline (`view::Fold` lays the lines on the rows; `Soft::band` draws them); the status bar is off by default, `[window] status_bar`; cursor shape `[input] cursor`). Text is supersampled, vertically hinted and LCD sub-pixel (`font.rs`, `soft.rs`, ADR 0020; `[font] smoothing`/`hinting`). Chips are reordered by dragging in the settings panel. `[window] blur = true` asks the compositor to blur behind the glass (a request, `wl.rs`, ADR 0019; GNOME offers none). `[input] mode = "chips"` draws context chips on the line above the prompt (`bar.rs`, `context.rs`, `view::prompt_rows`, `history.rs` for each command's status and time, ADR 0018/0021; bash gets its hook from axon, `axon shell-init bash|zsh|fish` prints it for an rc file). Env overrides it: `AXON_FONT`, `AXON_FONT_SIZE` (15), `AXON_OPACITY` (0.93 `winit`, 0.88 `wl`), `AXON_DECORATIONS=1`.
- Between runs (ADR 0042, `restore.rs`, `wlapp/keep.rs`, `[windows] restore`): the windows, each in its shell's folder, with names and groups, are written to `~/.local/state/axon/session` as they change and opened again at the next start; one axon owns the file. A click on the line being typed moves the shell's cursor there by pressing the arrows (ADR 0043, `caret.rs`). A window that runs `claude`, `codex` or `agy` shows the agent's own mark, not a spinner (ADR 0044, 0046, `agent.rs`, `icons::agent`): faint while Claude Code works and with an amber dot while it waits, as the mark before its title says (`◐`/`◑`, `✳`; cut from the title, `status_mark`).
- Windows: one shell per window, windows in groups, listed in a panel or as tabs; **a group is the split view** (its windows are shown side by side as panes, `Ctrl+Space` splits and makes the group, ADR 0034; dragging the gap between two panes or `Alt+Shift+arrows` resizes them, `Alt+=` evens them, ADR 0045; `wlapp.rs`, `side.rs`, `panes.rs`, `groups.rs`, `dnd.rs`; ADRs 0023-0034); `Ctrl+K` command palette, `Alt+O` overview, `Alt+G` group dialog, right-click menus, an *Undo* toast for a close. All screens over the grid are overlays (`overlay.rs`, ADR 0025). Each window's shell starts in its own systemd scope (`[windows] scope`, `session.rs`, ADR 0038: so a monitor and `systemd-oomd` see a window, not "axon"; probed first, off where systemd's user manager does not answer).
- `AXON_BACKEND`: `wl` (default when `WAYLAND_DISPLAY` is set) or `winit` (+ `wgpu`, the X11 fallback; `wl` falls back to it by itself if it cannot start). `AXON_WL_DEBUG=1` traces the protocol. Debugging aids that start a screen or a state for screenshots and measurements (all in the README's table): `AXON_SETTINGS`, `AXON_OVERVIEW`, `AXON_WINDOWS=n`, `AXON_PANES=n`, `AXON_GROUPS`, `AXON_RUNNING`, `AXON_LIST_UI=dialog|menu|...`, `AXON_DEMO_OVERLAY=...`. A run with any of them neither reads nor writes the kept session; `AXON_SESSION=off|<file>` says where the session lives (`scripts/bench.sh` sets it off).

## Hard rules
1. Nothing on the UI thread that blocks or allocates per frame on the hot path.
2. No new dependencies without justifying the cost (binary size, startup, compile time).
3. Idle = 0% CPU: render only on demand (`ControlFlow::Wait`).
4. Verify the real UI after a visual change (the design board, `scripts/design.sh`); `cargo build` does not prove it looks right. Renderer refactors must be pixel-exact (method in `axon-data-oriented-design`).
5. No caches: do not add one, redesign the data instead. Flat arrays over hash tables, indices over pointers.
6. Prefer our own implementation to a new dependency; existing dependencies are scaffolding with an exit plan (`knowledge/plan/own-implementations.md`).
7. Keep the numbers current: after any change that can move binary size, memory or speed (code, dependencies, build profile, fonts), run `scripts/bench.sh` and update the README `Benchmarks` section (tables, date, commit and a new history row) and `knowledge/performance/` in the same change. Never leave stale numbers.
