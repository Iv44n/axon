# 0022 · The interface speaks English and Spanish

**Decision:** every string the window draws (settings screen, status bar hints, the preview, the save error) is in
`src/i18n.rs`, once per language, in one list: a `strings!` macro builds the enum of keys and both tables from the same
lines, so a string cannot exist in one language only, and a test checks both tables (same length, none empty, the same
backticked commands). `tr(Str::Save)` is an array index, no allocation, no cache, no dependency (no gettext, no
fluent): two languages in a 100-line file are cheaper than a catalogue format.

**Choosing:** `[ui] language = "auto" | "en" | "es"`, also the last row of the settings screen's Font page, applied live like
the other rows. `auto` reads `LC_ALL`, `LC_MESSAGES`, `LANG` in that order (empty ones skipped) and means Spanish when the
first starts with `es`, English otherwise. The language in use is one process-wide byte (`i18n::set`), set at start, on a
reload (`Ctrl+Shift+R`) and when the draft changes.

**What is translated and what is not:** the window's text is. The config file (keys, comments), `axon` command-line output
(`config show`, `shell-init`, errors), the shell hooks, the chip names in the file (`dir`, `branch`...) and the logs stay in
English: they are read by tools and documentation. The chip names in the settings grid are translated for display only
(`hora`, `carpeta`, `rama`...); `chip.name()` is still what the file says. The design board has `settings-es`,
`settings-es-input` and `chips-es`.

**Adding a language or a string:** add the lines to `strings!` (one column per language; a new language is a third table and a
`Lang` variant) and use `tr`. Check the longest string against its box on the board: Spanish runs 20-30% longer, which is why
the Mode choices are 150 px wide and the Font page hint is shortened.
